# Python Exception Handling Improvements

## Current State
The Cloud-Reaper codebase contains 100+ instances of broad `except Exception` handling in `src/reaper/web/app_async.py` and other Python files. While this provides error handling, it can mask specific errors and make debugging difficult.

## Recommended Improvements

### 1. Import Statement Error Handling
**Current:**
```python
try:
    from weasyprint import HTML
except Exception as e:
    HTML = None
    print(f"[*] WeasyPrint could not be loaded: {e}")
```

**Improved:**
```python
try:
    from weasyprint import HTML
except ImportError as e:
    HTML = None
    print(f"[*] WeasyPrint could not be loaded: {e}")
```

### 2. API Call Error Handling
**Current:**
```python
try:
    result = some_api_call()
except Exception as e:
    logger.error(f"API call failed: {e}")
    return None
```

**Improved:**
```python
try:
    result = some_api_call()
except ConnectionError as e:
    logger.error(f"Connection failed: {e}")
    return None
except TimeoutError as e:
    logger.error(f"Request timeout: {e}")
    return None
except ValueError as e:
    logger.error(f"Invalid response: {e}")
    return None
except Exception as e:
    logger.error(f"Unexpected error: {e}")
    return None
```

### 3. Database Operation Error Handling
**Current:**
```python
try:
    db.execute(query)
except Exception as e:
    logger.error(f"Database error: {e}")
```

**Improved:**
```python
try:
    db.execute(query)
except sqlite3.OperationalError as e:
    logger.error(f"Database operation failed: {e}")
except sqlite3.IntegrityError as e:
    logger.error(f"Database integrity error: {e}")
except Exception as e:
    logger.error(f"Unexpected database error: {e}")
```

### 4. File Operation Error Handling
**Current:**
```python
try:
    with open(filename, 'r') as f:
        data = f.read()
except Exception as e:
    logger.error(f"File error: {e}")
```

**Improved:**
```python
try:
    with open(filename, 'r') as f:
        data = f.read()
except FileNotFoundError as e:
    logger.error(f"File not found: {e}")
except PermissionError as e:
    logger.error(f"Permission denied: {e}")
except IOError as e:
    logger.error(f"I/O error: {e}")
```

## Implementation Strategy

### Phase 1: Critical Paths
1. Focus on database operations first
2. Handle cloud provider API calls specifically
3. Improve file operations error handling

### Phase 2: API Endpoints
1. Review each FastAPI endpoint
2. Add specific exception handling for common errors
3. Ensure proper HTTP status codes are returned

### Phase 3: Background Tasks
1. Improve error handling in async background tasks
2. Add proper logging for different error types
3. Implement retry logic for transient errors

## Best Practices

1. **Always handle specific exceptions first**: Catch specific exceptions before generic ones
2. **Log with context**: Include relevant information when logging errors
3. **Don't silently swallow errors**: Even if you handle an error, log it appropriately
4. **Use appropriate HTTP status codes**: Map different exceptions to proper HTTP responses
5. **Consider retry logic**: For transient errors like network issues
6. **Document expected exceptions**: Make it clear what exceptions a function might raise

## Tools for Improvement

1. **Static Analysis**: Use tools like `pylint` or `flake8` to catch broad exception handling
2. **Code Review**: Establish guidelines for exception handling in code reviews
3. **Testing**: Write tests that verify error handling paths
4. **Monitoring**: Set up monitoring to track different types of errors

## Priority Areas for Immediate Action

1. **Security-sensitive operations**: Authentication, authorization, credential handling
2. **Data persistence**: Database operations, file writes
3. **External API calls**: Cloud provider APIs, third-party services
4. **User-facing operations**: Actions that directly affect user experience

## Example: Improved FastAPI Endpoint

```python
@app.post("/api/resources")
async def create_resource(resource: ResourceCreate):
    try:
        # Validate input
        if not resource.name:
            raise ValueError("Resource name is required")
        
        # Database operation
        resource_id = await db.create_resource(resource)
        
        # Background task
        await background_task_queue.enqueue(
            "initialize_resource", 
            resource_id=resource_id
        )
        
        return {"id": resource_id, "status": "created"}
        
    except ValueError as e:
        raise HTTPException(status_code=400, detail=str(e))
    except DatabaseError as e:
        logger.error(f"Database error creating resource: {e}")
        raise HTTPException(status_code=500, detail="Database operation failed")
    except Exception as e:
        logger.error(f"Unexpected error creating resource: {e}")
        raise HTTPException(status_code=500, detail="Internal server error")
```

## Conclusion

While broad exception handling provides basic error coverage, specific exception handling improves:
- Debugging capabilities
- Error recovery strategies  
- User experience through better error messages
- System reliability through targeted error handling

Implement these improvements incrementally, starting with the most critical paths.
