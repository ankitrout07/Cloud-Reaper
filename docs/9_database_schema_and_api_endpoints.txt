PART 5: DATABASE SCHEMAS, CRYPTOGRAPHIC VAULT, APIS & DEV TOOLS

This final section covers Cloud-Reaper's data persistence model, its high-security
cryptographic credential vault, web API structures, and developer tool chains.


1. RELATIONAL DATABASE persistence DATA MODELS (models.py)
-----------------------------------------------------------
* Location: `src/reaper/engine/models.py`
* Implementation: Utilizes PostgreSQL (SQLAlchemy 2.0 Declarative ORM) as the core
  data persistence layer. The database contains 10 primary tables:

  1. `resources` (Table: Resource)
     - Stores the inventory of discovered virtual machines, networks, and disks.
     - Columns: `id` (String primary key), `name`, `type`, `region`, `tags` (JSONB),
       `active` (Boolean), `is_protected` (Boolean), `is_unallocated` (Boolean),
       `last_seen` (DateTime).
     - Relations: Connects to CostHistory, ReapAction, Recommendation, and ActionLog.

  2. `cost_history` (Table: CostHistory)
     - Tracks daily costs per resource for historical regression analysis.
     - Columns: `id`, `resource_id` (ForeignKey), `date`, `cost` (Numeric 15,4),
       `cost_type` (String: ACTUAL or AMORTIZED), `currency` (String).

  3. `reap_actions` (Table: ReapAction)
     - Audit trail of automated deallocations or terminations.
     - Columns: `id`, `resource_id` (ForeignKey), `action` (e.g., DEALLOCATE, DELETE),
       `authorized_by`, `timestamp`.

  4. `recommendations` (Table: Recommendation)
     - Holds active optimization plans generated by the AI/ML engines.
     - Columns: `id`, `resource_id` (ForeignKey), `recommendation_type` (RIGHTSIZE,
       GREENOPS), `savings` (Numeric 15,4), `description`.

  5. `action_logs` (Table: ActionLog)
     - General logging of compliance auditing, manual overrides, and system tasks.
     - Columns: `id`, `resource_id` (ForeignKey), `action_type` (REAP, KILL,
       PROTECTION_ADD), `status` (SUCCESS, FAILED), `details`, `timestamp`.

  6. `business_metrics` (Table: BusinessMetric)
     - Logs non-cloud business metrics for marginal unit economics correlation.
     - Columns: `id`, `metric_name` (e.g., ACTIVE_USERS, API_REQUESTS), `value` (Float),
       `unit` (String), `date`.

  7. `region_price_cache` (Table: RegionPriceCache)
     - Local pricing cache to speed up regional price lookups.
     - Columns: `id`, `sku_id` (index), `region_name` (index), `price` (Numeric 15,6),
       `currency`, `last_updated`.

  8. `vault_settings` (Table: VaultSettings)
     - Single-row configuration record storing vault encryption settings.
     - Columns: `id` (default 1), `salt` (Base64 string), `passcode_verifier` (salted
       password hash), `created_at`, `updated_at`.

  9. `vault_entries` (Table: VaultEntry)
     - Holds encrypted secrets (cloud API keys, service accounts).
     - Columns: `id`, `label`, `entry_type` (credential, passcode, note),
       `encrypted_payload` (Base64 string), `created_at`, `updated_at`.

  10. `cloud_connections` (Table: CloudConnection)
      - Managed credentials for AWS, Azure, GCP, and Kubernetes clusters.
      - Columns: `id`, `provider_type` (azure, aws, gcp, k8s), `connection_name`,
        `credentials` (JSONB), `is_active` (Boolean), `created_at`, `updated_at`.


2. CRYPTOGRAPHIC SECRET VAULT DESIGN (vault_crypto.py)
-------------------------------------------------------
* Location: `src/reaper/web/vault_crypto.py` & `src/reaper/web/app.py`
* Security Paradigm: Cloud-Reaper manages highly sensitive cloud credentials. To
  keep secrets safe, it implements a secure cryptographic vault based on industry best
  practices:
  - High-Entropy Salt Generation: Generates unique 16-byte cryptographically secure
    salts:
    `os.urandom(16)`
  - Passcode Verification: Hashes passcodes using PBKDF2-HMAC-SHA256 with 600,000
    iterations. This verifier hash is stored in `vault_settings` to validate the passcode
    before unlocking:
    `hashlib.pbkdf2_hmac("sha256", passcode.encode("utf-8"), salt, 600000)`
  - Fernet AES-128 Key Derivation: Derives unique 32-byte encryption keys from the
    passcode and salt using PBKDF2-HMAC-SHA256 with 100,000 iterations:
    `hashlib.pbkdf2_hmac("sha256", passcode.encode("utf-8"), salt, 100000)`
    This key is converted to a base64 string to initialize the Fernet symmetric encryption
    engine (`cryptography.fernet.Fernet`).
  - Session Security & Auto-Lock:
    - The derived key is stored in the encrypted browser session (`session["vault_fernet_key"]`)
      and is decrypted ONLY in-memory.
    - Session lifetime is capped by a strict Time-to-Live parameter (`VAULT_UNLOCK_TTL_SEC`,
      default 3600 seconds).
    - Locking the vault (`/api/vault/lock`) immediately purges all keys from the session:
      `session.pop("vault_fernet_key", None)`
    - Resetting the vault (`/api/vault/reset`) performs a full wipe, erasing all stored
      secrets and settings.


3. CORE WEB WEB API ENDPOINTS & ROUTING
---------------------------------------
Cloud-Reaper provides a robust REST API to manage credentials, configure the vault,
and run AI optimization scans:

* Settings & Context APIs:
  - `POST /api/settings/sync`: Synchronizes Azure credentials directly to the local `.env` file.
  - `POST /api/settings/update`: Endpoint to adjust active currency systems, trigger manual
    pricebook reloads, update rightsizing profiles, or configure sleep schedules.
  - `POST /api/settings/connect-azure`: Validates Azure credentials by running a test scan before saving.
  - `POST /api/settings/connect-cloud`: Connects new provider credentials (AWS, Azure, GCP, Kubernetes)
    and saves them in the database connection table.
  - `GET  /api/context/switch?provider=<type>`: Switches the active scanning context to the target provider.

* Cryptographic Secret Vault APIs:
  - `GET  /api/vault/status`: Returns whether the vault is configured and unlocked.
  - `POST /api/vault/setup`: Initializes the vault with a user-defined passcode.
  - `POST /api/vault/unlock`: Validates the passcode and unlocks the vault.
  - `POST /api/vault/lock`: Purges all keys from the session.
  - `POST /api/vault/reset`: Performs a full wipe of all entries.
  - `GET  /api/vault/entries`: Lists stored secret labels (payloads are not returned).
  - `POST /api/vault/entries`: Encrypts and saves a new secret payload.
  - `GET  /api/vault/entries/<id>`: Decrypts and returns a specific secret.
  - `DELETE /api/vault/entries/<id>`: Deletes a secret from the vault.

* Generative AI Copilot APIs:
  - `POST /api/v1/copilot/optimize`: The primary entry point for the AI Copilot. Accepts a JSON request body with
    `provider`, `intent`, and `budget_cap`, and returns a structured blueprint complete with calculated costs,
    savings metrics, and production-ready Terraform HCL.


4. DEV TOOLS & TESTING FRAMEWORKS
----------------------------------
To enforce code quality and simplify deployment, Cloud-Reaper includes a modern
developer toolchain:

* Makefile Tasks:
  - `make install`: Sets up a virtual environment and installs all runtime and dev dependencies.
  - `make build`: Compiles the high-velocity Go core scraper to `bin/reaper-engine`.
  - `make test`: Runs Python unit tests and Go tests.
  - `make lint`: Performs Ruff code format checks, Mypy static type analysis, and Golangci-lint runs.
  - `make run`: Launches the PostgreSQL container, compiles the Go core, and starts the Flask server.

* Code Quality Configs (pyproject.toml):
  - Ruff: Enforces clean import sorting and Python syntax rules (e.g., UP, I, E, F).
  - Mypy: Enforces strict type checking, checking that all variables and functions are typed.
  - Pytest: Configures tests to use the `tests/` directory and generates coverage reports.

* One-Click Bootstrap System (bootstrap.py):
  - Detects the host Operating System (Windows, macOS, or Linux).
  - Locates or creates a virtual environment (`venv`).
  - Installs all dependencies from `requirements.txt` and `requirements-dev.txt`.
  - Automatically compiles the Go performance core, building `reaper-engine`.
  - Sets up the `.env` configuration file, prompting the user for credential values.
  - Initializes database schemas and starts the local Flask server on port 5001.
